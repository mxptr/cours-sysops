# TP 3 – Premier déploiement Kubernetes

## Objectifs

* Découvrir un cluster Kubernetes local.
* Créer un Namespace.
* Déployer une application avec un Deployment.
* Observer les Pods créés par Kubernetes.
* Exposer l'application avec un Service.
* Accéder à l'application avec `kubectl port-forward`.
* Comprendre la relation entre Deployment, Pod et Service.

---

## Pré-requis

Avant de commencer, vous devez disposer de :

* Docker
* kubectl
* Kind
* l'image `cours-sysops:tp2` publiée sur GHCR

Vous devez également connaître votre nom d'utilisateur GitHub.

L'image utilisée dans ce TP est :

```text
ghcr.io/VOTRE_USERNAME/cours-sysops:tp2
```

---

# 1. Créer un cluster Kubernetes local

Créer un cluster Kind :

```bash
kind create cluster --name sysops
```

Vérifier que le cluster est accessible :

```bash
kubectl cluster-info
```

Vérifier les nœuds :

```bash
kubectl get nodes
```

Vous devez obtenir un nœud Kubernetes en état :

```text
Ready
```

### Question

Quel est le rôle d'un nœud Kubernetes ?

---

# 2. Créer le Namespace

Créer le fichier :

```text
namespace.yaml
```

avec le contenu suivant :

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: sysops
```

Appliquer le manifeste :

```bash
kubectl apply -f namespace.yaml
```

Vérifier :

```bash
kubectl get namespaces
```

Vous devez retrouver :

```text
sysops
```

---

# 3. Créer le Deployment

Créer le fichier :

```text
deployment.yaml
```

Utiliser le manifeste suivant :

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: cours-sysops
  namespace: sysops
spec:
  replicas: 1
  selector:
    matchLabels:
      app: cours-sysops
  template:
    metadata:
      labels:
        app: cours-sysops
    spec:
      containers:
        - name: cours-sysops
          image: ghcr.io/VOTRE_USERNAME/cours-sysops:tp2
          ports:
            - containerPort: 5000
```

Remplacez :

```text
VOTRE_USERNAME
```

par votre nom d'utilisateur GitHub.

---

# 4. Déployer l'application

Appliquer le Deployment :

```bash
kubectl apply -f deployment.yaml
```

Vérifier le Deployment :

```bash
kubectl get deployments -n sysops
```

Vérifier les Pods :

```bash
kubectl get pods -n sysops
```

Vous devez obtenir un Pod en état :

```text
Running
```

---

# 5. Observer le Pod

Afficher davantage d'informations :

```bash
kubectl describe pod -n sysops <NOM_DU_POD>
```

Pour récupérer facilement le nom du Pod :

```bash
kubectl get pods -n sysops
```

Observer les logs :

```bash
kubectl logs -n sysops <NOM_DU_POD>
```

# 6. Tester le self-healing

Supprimer le Pod :

```bash
kubectl delete pod -n sysops <NOM_DU_POD>
```

Observer immédiatement :

```bash
kubectl get pods -n sysops
```

Puis :

```bash
kubectl get pods -n sysops -w
```

Vous devriez observer la création d'un nouveau Pod.

Arrêter l'observation avec :

```text
Ctrl+C
```

### Question

Pourquoi Kubernetes recrée-t-il automatiquement le Pod ?

---

# 7. Créer le Service

Le Pod ne doit pas être considéré comme le point d'accès stable à l'application.

Créer le fichier :

```text
service.yaml
```

avec :

```yaml
apiVersion: v1
kind: Service
metadata:
  name: cours-sysops
  namespace: sysops
spec:
  selector:
    app: cours-sysops
  ports:
    - port: 80
      targetPort: 5000
  type: ClusterIP
```

Appliquer le Service :

```bash
kubectl apply -f service.yaml
```

Vérifier :

```bash
kubectl get services -n sysops
```

Vous devez retrouver :

```text
cours-sysops
```

---

# 8. Comprendre le mapping des ports

Le Service utilise :

```yaml
port: 80
targetPort: 5000
```

Cela signifie :

```text
Service
  port 80
     ↓
Pod
  port 5000
     ↓
Application Flask
  port 5000
```

### Question

Pourquoi le Service utilise-t-il le port `80` alors que l'application écoute sur le port `5000` ?

---

# 9. Vérifier les endpoints du Service

Afficher les endpoints :

```bash
kubectl get endpoints -n sysops
```

Vous devez retrouver l'adresse du Pod.

Vous pouvez également utiliser :

```bash
kubectl describe service cours-sysops -n sysops
```

Identifier notamment :

* le selector ;
* le port ;
* le targetPort ;
* les endpoints.

### Question

À quoi sert le selector :

```yaml
selector:
  app: cours-sysops
```

---

# 10. Accéder à l'application

Le Service est de type `ClusterIP`.

Il n'est donc pas directement accessible depuis votre machine.

Utiliser `kubectl port-forward` :

```bash
kubectl port-forward -n sysops svc/cours-sysops 8080:80
```

Vous devez obtenir un message similaire à :

```text
Forwarding from 127.0.0.1:8080 -> 80
```

Laisser cette commande fonctionner.

---

# 11. Tester l'application

Dans un autre terminal :

```bash
curl http://localhost:8080
```

Tester également la route de santé :

```bash
curl http://localhost:8080/health
```

La réponse attendue est :

```json
{"status":"ok"}
```

Vous pouvez également ouvrir :

```text
http://localhost:8080
```

dans votre navigateur.

---

# 12. Observer la chaîne complète

Afficher les ressources Kubernetes :

```bash
kubectl get all -n sysops
```

Vous devez retrouver notamment :

```text
Deployment
Pod
Service
ReplicaSet
```

Représenter la chaîne :

```text
Deployment
     │
     ▼
ReplicaSet
     │
     ▼
Pod
     │
     ▼
Application Flask
```

Et pour l'accès réseau :

```text
Navigateur / curl
       │
       ▼
port-forward
       │
       ▼
Service :80
       │
       ▼
Pod :5000
       │
       ▼
Flask
```
