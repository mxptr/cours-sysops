# TP 6 – Pipeline CI/CD complet avec Kubernetes

## Objectifs

* Comprendre le fonctionnement d'un pipeline CI/CD complet.
* Automatiser la construction et la publication d'une image Docker.
* Créer automatiquement un cluster Kubernetes avec Kind.
* Déployer automatiquement l'application sur Kubernetes.
* Utiliser le SHA du commit pour versionner l'image.
* Vérifier automatiquement le déploiement.
* Tester automatiquement que l'application fonctionne.

# 5. Créer le workflow CI/CD

Créer ou remplacer le fichier :

```text
.github/workflows/cicd.yml
```

avec le contenu suivant :

```yaml
name: CI/CD with Kind

on:
  push:
    branches:
      - main

permissions:
  contents: read
  packages: write

jobs:
  build-and-deploy:

    runs-on: ubuntu-latest

    steps:

      # --------------------------------------------------
      # 1. Récupérer le code
      # --------------------------------------------------

      - name: Checkout
        uses: actions/checkout@v4


      # --------------------------------------------------
      # 2. Créer un cluster Kubernetes temporaire
      # --------------------------------------------------

      - name: Create Kind cluster
        uses: helm/kind-action@v1


      # --------------------------------------------------
      # 3. Se connecter à GHCR
      # --------------------------------------------------

      - name: Login to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}


      # --------------------------------------------------
      # 4. Construire l'image Docker
      # --------------------------------------------------

      - name: Build Docker image
        run: |
          docker build \
            -t ghcr.io/${{ github.repository_owner }}/cours-sysops:${{ github.sha }} \
            -t cours-sysops:${{ github.sha }} .


      # --------------------------------------------------
      # 5. Publier l'image dans GHCR
      # --------------------------------------------------

      - name: Push image to GHCR
        run: |
          docker push \
            ghcr.io/${{ github.repository_owner }}/cours-sysops:${{ github.sha }}


      # --------------------------------------------------
      # 6. Charger l'image dans Kind
      # --------------------------------------------------

      - name: Load image into Kind
        run: |
          kind load docker-image cours-sysops:${{ github.sha }}


      # --------------------------------------------------
      # 7. Créer le namespace
      # --------------------------------------------------

      - name: Create namespace
        run: |
          kubectl apply -f namespace.yaml


      # --------------------------------------------------
      # 8. Déployer la configuration
      # --------------------------------------------------

      - name: Deploy configuration
        run: |
          kubectl apply -f configmap.yaml
          kubectl apply -f secret.yaml


      # --------------------------------------------------
      # 9. Déployer l'application
      # --------------------------------------------------

      - name: Deploy application
        run: |
          kubectl apply -f deployment.yaml
          kubectl apply -f service.yaml


      # --------------------------------------------------
      # 10. Utiliser l'image construite par le pipeline
      # --------------------------------------------------

      - name: Set image
        run: |
          kubectl set image deployment/cours-sysops \
            cours-sysops=cours-sysops:${{ github.sha }} \
            -n sysops


      # --------------------------------------------------
      # 11. Empêcher Kubernetes de chercher l'image
      #     dans un registry externe
      # --------------------------------------------------

      - name: Configure image pull policy
        run: |
          kubectl patch deployment cours-sysops \
            -n sysops \
            --type=strategic \
            -p '{"spec":{"template":{"spec":{"containers":[{"name":"cours-sysops","imagePullPolicy":"Never"}]}}}}'


      # --------------------------------------------------
      # 12. Attendre le déploiement
      # --------------------------------------------------

      - name: Wait for rollout
        run: |
          kubectl rollout status \
            deployment/cours-sysops \
            -n sysops


      # --------------------------------------------------
      # 13. Vérifier les ressources Kubernetes
      # --------------------------------------------------

      - name: Check Kubernetes resources
        run: |
          kubectl get pods -n sysops
          kubectl get deployment -n sysops
          kubectl get service -n sysops


      # --------------------------------------------------
      # 14. Tester l'application
      # --------------------------------------------------

      - name: Test application
        run: |

          kubectl port-forward \
            -n sysops \
            svc/cours-sysops \
            8080:80 \
            > /tmp/port-forward.log 2>&1 &

          for i in $(seq 1 30); do

            if curl -fsS http://localhost:8080; then
              echo "Application is responding"
              exit 0
            fi

            sleep 2

          done

          echo "Application test failed"

          cat /tmp/port-forward.log

          exit 1
```

# 6. Comprendre le pipeline

Le workflow contient plusieurs étapes.

## Étape 1 – Checkout

```yaml
- name: Checkout
  uses: actions/checkout@v4
```

GitHub Actions récupère le contenu du dépôt.

```text
GitHub
   ↓
Runner
   ↓
Code source
```

---

# 7. Étape 2 – Créer Kubernetes

```yaml
- name: Create Kind cluster
  uses: helm/kind-action@v1
```

Un cluster Kubernetes Kind est créé directement dans le runner GitHub Actions.

Le cluster est temporaire.

```text
GitHub Runner

┌──────────────────────────────┐
│                              │
│       Kind                   │
│                              │
│   Kubernetes cluster         │
│                              │
│   ┌──────────────────────┐   │
│   │ cours-sysops         │   │
│   │ Pod                  │   │
│   └──────────────────────┘   │
│                              │
└──────────────────────────────┘
```

Le cluster sera supprimé lorsque le runner sera détruit.

---

# 8. Étape 3 – Connexion à GHCR

```yaml
- name: Login to GHCR
  uses: docker/login-action@v3
```

Le workflow utilise :

```text
GITHUB_TOKEN
```

pour s'authentifier auprès de GitHub Container Registry.

Aucun token personnel n'est nécessaire dans ce workflow.

---

# 9. Étape 4 – Construire l'image

L'image est construite avec deux tags :

```bash
docker build \
  -t ghcr.io/${{ github.repository_owner }}/cours-sysops:${{ github.sha }} \
  -t cours-sysops:${{ github.sha }} .
```

Nous obtenons deux références vers la même image :

```text
ghcr.io/USERNAME/cours-sysops:SHA
cours-sysops:SHA
```

La première sera publiée dans GHCR.

La seconde sera chargée directement dans Kind.

---

# 10. Pourquoi utiliser le SHA ?

Le workflow utilise :

```text
${{ github.sha }}
```

pour identifier l'image.

Par exemple :

```text
cours-sysops:8f3c2a1...
```

Le SHA permet d'associer :

```text
Commit
  ↓
Image
  ↓
Déploiement
```

Chaque exécution du pipeline produit ainsi une version identifiable.

L'image est publiée avec :

```bash
  ghcr.io/${{ github.repository_owner }}/cours-sysops:${{ github.sha }}
```

La chaîne devient :

```text
Code
 ↓

 ↓
Docker image
 ↓
```

# 12. Étape 6 – Charger l'image dans Kind

Le runner possède déjà l'image localement.

Nous pouvons donc la charger directement dans Kind :

```bash
kind load docker-image cours-sysops:${{ github.sha }}
```

La chaîne devient :

```text
Docker image
      ↓
   Kind
      ↓
 Kubernetes
```

Cette étape évite de demander au cluster Kind de télécharger l'image depuis GHCR.

---

# 13. Étape 7 – Déployer Kubernetes

Le workflow applique les manifests :

```bash
kubectl apply -f namespace.yaml
```

Puis :

```bash
kubectl apply -f configmap.yaml
kubectl apply -f secret.yaml
```

Puis :

```bash

```

---

# 14. Étape 8 – Utiliser l'image du pipeline

Le Deployment initial contient une image.

Le pipeline remplace cette image avec :

```bash
kubectl set image deployment/cours-sysops \
  cours-sysops=cours-sysops:${{ github.sha }} \
  -n sysops
```

Le Deployment utilise alors l'image construite pendant cette exécution du pipeline.

---

# 15. Pourquoi `imagePullPolicy: Never` ?

L'image a déjà été chargée dans Kind :

```text
Docker
  ↓
kind load
  ↓
Kind
```

Nous demandons donc à Kubernetes de ne pas essayer de télécharger l'image depuis un registry :

```yaml
imagePullPolicy: Never
```

Cela permet au Pod d'utiliser directement l'image présente dans le cluster Kind.

---

# 16. Étape 9 – Attendre le déploiement

Le pipeline utilise :

```bash
kubectl rollout status \
  deployment/cours-sysops \
  -n sysops
```

Cette commande attend que le Deployment soit correctement déployé.

Si le déploiement échoue, le workflow échoue également.
