# TP 5 – Premier workflow GitHub Actions

## Objectifs

* Découvrir GitHub Actions.
* Comprendre la structure d'un workflow.
* Automatiser la construction d'une image Docker.
* Publier automatiquement l'image sur GitHub Container Registry (GHCR).
* Utiliser le SHA du commit comme identifiant de version.
* Vérifier l'exécution d'un workflow dans GitHub.

## Continuité avec les TPs précédents

Dans les TPs précédents, les opérations étaient réalisées manuellement :

```text
Code
  ↓
docker build
  ↓
docker tag
  ↓
docker push
```

Dans ce TP, GitHub Actions va automatiser ces opérations :

```text
git push
   ↓
GitHub Actions
   ↓
docker build
   ↓
docker push
   ↓
GHCR
```

Le déploiement Kubernetes n'est pas encore automatisé.

Il sera réalisé dans le TP6.

## 3. Découvrir GitHub Actions

GitHub Actions permet d'exécuter automatiquement des tâches à partir d'événements GitHub.

Un workflow est défini dans un fichier YAML placé dans :

```text
.github/workflows/
```

Créer le répertoire :

```bash
mkdir -p .github/workflows
```

---

## 4. Créer le workflow

Créer le fichier :

```text
.github/workflows/ci.yml
```

avec le contenu suivant :

```yaml
name: Build and Push Docker Image

on:
  push:
    branches:
      - main

permissions:
  contents: read
  packages: write

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Login to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and Push Docker Image
        uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: ghcr.io/VOTRE_USERNAME/cours-sysops:${{ github.sha }}
```

Remplacer :

```text
VOTRE_USERNAME
```

par votre nom d'utilisateur GitHub.

---

## 5. Comprendre le workflow

Observer la structure du fichier.

### Le nom du workflow

```yaml
name: Build and Push Docker Image
```

Il permet d'identifier le workflow dans l'interface GitHub.

---

### Le déclencheur

```yaml
on:
  push:
    branches:
      - main
```

Le workflow est exécuté lorsqu'un commit est poussé sur la branche `main`.

---

### Les permissions

```yaml
permissions:
  contents: read
  packages: write
```

Elles permettent au workflow :

* de lire le contenu du dépôt ;
* de publier une image dans GHCR.

---

### Le runner

```yaml
runs-on: ubuntu-latest
```

Le job est exécuté sur une machine virtuelle Ubuntu fournie par GitHub Actions.

---

### Checkout

```yaml
- name: Checkout
  uses: actions/checkout@v4
```

Cette étape récupère le contenu du dépôt sur le runner.

---

### Connexion à GHCR

```yaml
- name: Login to GHCR
  uses: docker/login-action@v3
  with:
    registry: ghcr.io
    username: ${{ github.actor }}
    password: ${{ secrets.GITHUB_TOKEN }}
```

Le workflow s'authentifie auprès de GitHub Container Registry.

Le token :

```text
GITHUB_TOKEN
```

est fourni automatiquement par GitHub Actions.

Il n'est donc pas nécessaire de créer un Personal Access Token pour ce workflow.

---

### Build et Push

```yaml
- name: Build and Push Docker Image
  uses: docker/build-push-action@v6
  with:
    context: .
    push: true
    tags: ghcr.io/VOTRE_USERNAME/cours-sysops:${{ github.sha }}
```

Cette étape réalise deux opérations :

```text
docker build
      +
docker push
```

L'image est publiée dans GHCR.

---

## 6. Comprendre le tag avec le SHA

Le workflow utilise :

```yaml
${{ github.sha }}
```

pour identifier l'image.

Par exemple :

```text
ghcr.io/oboyo/cours-sysops:8f3c2a1...
```

Le SHA correspond au commit qui a déclenché le workflow.

Cela permet d'associer directement :

```text
Commit Git
    ↓
Image Docker
    ↓
Version déployable
```

Chaque commit peut donc produire une image identifiable.
